# 项目问题台账性能验证

验证日期：2026-11-13。范围为 PC 端项目问题台账，保持现有项目、资产、扫描、审核和归档报告数据。

## 问题与改动

原实现为每个来源扫描生成完整报告数据，回读全部问题的源码快照并加载审核长文本，最后在内存中筛选分页。筛选、分页和初始化的多个监听也会触发重复请求。

- 数据库完成范围统计、筛选、排序和分页；只加载当前页的问题详情并回读源码。
- 报告采纳只读取政策判断字段，复用原双轮审核、人工结论与去重规则；已归档报告只提取原始问题 ID，不重新计算归档内容。
- 审核存在性按本轮来源扫描批量读取，避免逐问题查询；未完成审核的政策判断不逐项读取任务描述。
- 首次进入、筛选、翻页和主动查询分别只发起一次问题请求。快速切换时取消旧请求，使用请求序号保护最新结果。
- 汇总与分页在同一只读事务中读取。不增加跨请求缓存，审核变更仍按实际数据库结果刷新。

## 实测

本机现有 Docker 部署、同一资产扫描范围共 **8,064 条问题**，请求当前页 20 条。优化前实测 15.226 秒；优化后连续三次约 0.10～0.20 秒。该结果是本次环境和数据下的接口耗时，不代表其他机器、源码文件大小或并发负载下的固定承诺。

另验证项目全部资产共 8,074 条、高危筛选共 6,032 条、末页仅 4 条和每页 100 条均能正常返回。逐项对比优化前后首屏原问题编号、排序、所属资产、报告采纳状态、总条数及范围统计，结果一致。

## 报告大数据量与审核进度恢复（2026-11-13）

报告列表进一步改为只读取采纳政策、原始问题身份、变化状态和依赖分组字段，不生成完整报告、不回读源码，也不加载审核长文本。归档列表通过流式解析保留原采纳清单及其统计。正文仅为采纳项回读源码；同一报告使用有界读取会话复用相同源文件，避免数千次重复读取。缓存不跨请求复用，并保留目录、符号链接、大小和二进制文件校验。

同一 8,064 条问题资产的报告列表实测从 17.076 秒降至 0.06～0.12 秒。原已归档项目的报告列表统计逐项比对一致。

项目台账进入后自动恢复每个来源扫描的最新持久化审核任务；“查看审核进度”展示任务编号、完成/失败数量、进度条及开始时间，运行中每 5 秒刷新。离开页面只释放轮询，重新进入恢复原任务，不重新提交审核。进度接口失败时显示重试提示并保留已知结果，禁止据此重复启动。依赖漏洞沿用合并审核单元计数。

回归增加万条问题列表与正文、请求内源码复用、跨请求/目录隔离及报告实例角色测试。完整后端构建共 237 项测试，0 失败、0 错误、1 跳过；PC 浏览器只读测试验证离开再返回恢复相同任务，且不产生审核提交请求：

```sh
cd codesentry-web
CODESENTRY_WEB_URL=http://127.0.0.1:5173 \
CODESENTRY_LEDGER_PROJECT_ID=<已有审核任务的项目ID> \
node scripts/review-progress-smoke.mjs
```

## 分类预审与审核费用控制（2026-11-13）

按批准的①分类分流、②规则预审、③结果复用和⑤预览预算实施。本地模型不在本次范围内。原已停止审核、原始台账、人工结论与旧报告归档不改写。

- 精确规则分类：内置明确的命名、注释等规范规则；安全类别继续保留候选，未知规则先人工分类。系统设置允许维护具体规则及依据，版本变化使预览和缓存失效。
- 预审：规范给出规则模板；依赖默认核对版本依据；缺少源码、样例线索和通用审计线索保留人工核实，不据此当作误报。凭据不进行登录或有效性试探。
- 台账按分类在数据库筛选后分页，规范不占默认安全候选指标。规范清单 CSV 保留原问题和来源，兼容 Excel 并防止公式注入。新安全报告不混入规范；原归档保留原范围。
- 付费默认关闭。旧模型审核入口拒绝绕过预览，单项和批量入口统一经过 15 分钟有效的范围预览及预算确认，重复提交同一预览返回原任务。
- 每批请求、输入/输出占额、费用与系统日费用共同限制调用；保守占额在数据库事务中原子预留，模型内部截断重试与失败重试也受限制。预算耗尽不把未处理项写成误报或模型失败。完整实际 usage 另行计数，未知用量不写成零费用。
- 复用仅限同资产、干净且相同的完整提交/制品、同一模型及规则/提示词版本与相关上下文，保存来源编号。脏工作区或缺少完整版本标识不跨扫描复用；缓存写入失败不重复付费审核。双轮记录与复用来源一起事务提交。
