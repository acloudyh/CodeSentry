# CodeSentry 规范整改与评审记录

适用规范：`docs/engineering-standards.md`。AI 代码执行与人工代码相同的检查；扫描通过不能代替人工评审。

## 本批次兼容契约

- v1 成功响应保持原结构，错误改为 RFC 9457 Problem，保留 `success:false`、`message` 兼容旧客户端。
- 错误不返回堆栈、SQL、异常原文、凭据和内部地址；字段错误不回传提交值。
- traceId 为 32 位小写十六进制；只接受合法上游 traceId。响应头和错误体保持一致。
- 报告分页范围 1–100，默认 20；非法范围返回 400，不静默截断。
- 认证方式、旧接口批量 v2 迁移、TLS 上线均需独立评审；当前成功协议不在没有迁移期的情况下替换。

## 审查边界

契约已静态检查并纳入版本控制；负责人签核仍待 PR 评审，不把本次自动校验描述成人工批准。按 COL-04，CI 和鉴权需要两名评审人。

## 原始自检

- Semgrep 本地扫描：4 个审计点，3 个是本地工具/钥匙串进程调用，1 个是迁移中的常量 SQL 拼接；需结合数据来源复核，不能视为已证实注入。
- npm audit：Vue / server-renderer、source-map-js、Vite 共 4 个高危依赖条目。
- secrets 扫描：命中本地忽略的临时扫描产物；不得将这些产物或秘密匹配原文提交。
