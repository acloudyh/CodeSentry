# CodeSentry 规范整改与评审记录

适用规范：`docs/engineering-standards.md`。AI 代码执行与人工代码相同的检查；扫描通过不能代替人工评审。

## 本批次兼容契约

- v1 成功响应保持原结构，错误改为 RFC 9457 Problem，保留 `success:false`、`message` 兼容旧客户端。
- 错误不返回堆栈、SQL、异常原文、凭据和内部地址；字段错误不回传提交值。
- traceId 为 32 位小写十六进制；只接受合法上游 traceId。响应头和错误体保持一致。
- 报告分页范围 1–100，默认 20；非法范围返回 400，不静默截断。
- 认证方式、旧接口批量 v2 迁移、TLS 上线均需独立评审；当前成功协议不在没有迁移期的情况下替换。

## 审查边界

契约已静态检查并纳入版本控制；负责人签核仍待 PR 评审，不把本次自动校验描述成人工批准。按 COL-04，CI 和鉴权需要两名评审人。

## 原始自检

- Semgrep 本地扫描：4 个审计点，3 个是本地工具/钥匙串进程调用，1 个是迁移中的常量 SQL 拼接；需结合数据来源复核，不能视为已证实注入。
- npm audit：Vue / server-renderer、source-map-js、Vite 共 4 个高危依赖条目。
- secrets 扫描：命中本地忽略的临时扫描产物；不得将这些产物或秘密匹配原文提交。

后续实施结果、测试证据和未解决项在本文件更新。

## 归档契约变更

增加 `POST /api/v2/report-archives`，以显式写请求冻结报告；旧 GET 导出仅查询或只读生成。项目首归档改为唯一键竞争胜出后读取，渲染过程不持有数据库行锁。v1 只读 URL 保持不变。新请求必须携带 Idempotency-Key，重复键不同来源返回 409。

创建业务项目、Git 凭据、工具配置统一使用 201 + Location；对应删除使用 204 无响应体。异步 ZIP 导出使用 202 + 任务 Location。前端接受全部成功 2xx；非法请求和失败继续使用 Problem。

## 自扫描审计项

社区快照来源为 `https://semgrep.dev/c/p/default`，版本 `ea8f32f673b7`，共 1074 条规则；加平台 OWASP/CWE 与前端规则，按 Java/前端语言选择适用规则执行。原始 JSON 和扫描日志只保存在忽略的 `tmp/`，不提交包含源码片段的临时产物。

- `CommandExecutor` 的 ProcessBuilder：平台执行扫描工具所必需，参数数组传递，无 shell 字符串拼接；具备取消、超时及诊断脱敏。社区标记为 LOW 置信度 audit，不自动改判误报。
- `MacOsKeychainAiApiKeyStore` 的 ProcessBuilder：固定 `/usr/bin/security find-generic-password`，仅读取既有钥匙串；已删除把密钥写进进程参数的遗留写入路径。社区标记为 LOW 置信度 audit，不屏蔽该规则。
- 原台账 SQL 分类条件拼接已改参数化；错误入口显式限制 HTTP 方法。

CI 对高风险、高置信度 SAST 结果阻断；未知置信度按 HIGH 处理，同时保存全部审计结果。扫描解析失败也阻断，不能把“未扫描”记为“没有问题”。

## 发布与未完成事项

1. 当前没有用户登录功能，不具备多人身份授权边界；不能对外宣称全条款完全合规。
2. 当前源码 secrets 检查不代表历史提交中已出现的运行凭据已撤销。共享数据库凭据的轮换须由负责人协调依赖系统，禁止在代码整改中直接改全局 MySQL 密码。
3. 旧 v1 的完整 schema、统一分页、统一幂等头和公开身份 DTO 迁移需独立契约评审；本批没有偷偷改变旧 ID 含义。
4. 新 CI 流程和分支保护需人工批准后在远端生效；当前不将本地通过描述为远端 CI 或生产已发布。
5. 生产部署前先核验已生成证书与信任、镜像扫描和备份。新增表向前兼容，回滚旧镜像时保留表，避免删除历史业务数据。

## 最终验收证据

机器可读摘要见 `verification-20261114.json`。本次全量后端测试 273 项，失败 0、错误 0，1 个显式联网用例按开关跳过；测试未调用真实付费模型。新增 Java/TS 可执行行覆盖率超过 90%。真实 HTTPS 使用独立测试库，验证保存、未知字段、字段校验、同源边界、只读 GET、幂等重放与冲突，并导出包含合成风险整改建议的 Word/PDF。

`.github/branch-protection-proposal.json` 是待批准配置，不是已生效的远端保护声明。源码 secrets 检查通过不表示历史凭据已失效；最终 npm 在线复核遇到本机 DNS 故障，保留此前有效审计结果，不把获取失败当作零漏洞。

前端最终补充使用同一最新 Trivy 库离线扫描 package-lock（含开发依赖）：高危 0、严重 0，保留 1 条 minimatch 中危；npm 的 8 个关联条目来自该依赖链。在线 npm API 失败没有被当成通过。

可观测性本批覆盖 HTTP traceId、错误展示与请求日志；完整 spanId 和跨后台任务链路传播尚未全部覆盖，不能宣称整个平台可观测性已完全满足。
